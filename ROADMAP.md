# Roadmap

Planned work and accepted debt. Remove an item when the change that resolves it merges.

## 0.7 API

0.7 changes the Python API where it is not Pythonic and the C++ API where it breaks the conventions, fixes the [memory safety](#memory-safety) and [behavior defects](#behavior-defects) items below and replaces the synthesizer with [FluidSynth](#features) in the same release. [MusicXML](#features) and the [MIDI message layer](#features) come after 0.7. The [code conventions](docs/development/conventions.md#python-api) state the target rules. For each item, decide the new form before implementing it. 0.7 removes the 0.6 forms outright, without deprecation shims, so that no compatibility layer outlives the release; the release notes carry the old-to-new table.

- **Copy and in-place forms.** `sort` and `filter` default to `inplace=True` (on scores, tracks and event lists), while `clip`, `shift_time`, `adjust_time` and the other transformations default to `inplace=False`. In C++, each transformation exists as `foo()` and `foo_inplace()` (`shift_time_inplace`, `clip_inplace`, `clip_with_sentinel_inplace`, ...); `Track` and `Score` `*_inplace` return `void` and the event `*_inplace` return a reference. Decided: apply [one form per operation](docs/development/conventions.md#design-rules) in both languages. Remove the `inplace` parameter and the `_inplace` names; `sort`, `filter`, `shift_time`, `shift_pitch`, `shift_velocity` and `adjust_time` mutate and return nothing, and `clip` and `trim` keep only the form that returns a new object. The binding's copy-or-in-place lambdas go with them.
- **Copy semantics.** `Score.copy()` and `Track.copy()` default to a deep copy, while `copy.copy` shares the tracks and event lists.
- **Queries.** `Note.end` is a property and `Track.end()`/`Score.end()` are methods; likewise `start`, `empty` and `note_num`. `symusic.Track.empty(ttype)` creates an empty track, while `track.empty()` tests for one.
- **Aliases and debugging API.** `tpq` duplicates `ticks_per_quarter`, `Score.from_file` takes both `fmt` and `format`, `Note.start` duplicates `time`, `Tempo.tempo` duplicates `qpm`, and `__use_count` exposes `shared_ptr` reference counts on public classes.
- **Strings for closed sets.** Time units (`ttype="tick"`, replaced as described under [per-unit classes](#07-api)), pianoroll modes, trim modes and file formats are strings matched at run time. Use enums or `Literal` types, and reject unknown values.
- **File I/O names.** Reading goes through `Score(path)`, `Score.from_file`, `from_midi(bytes)` and `from_abc(str)`; writing through `dump_midi(path)`, `dumps_midi()`, `dump_abc` and `dumps_abc`. `Score(x)` accepts a path, a ticks-per-quarter integer or another score in the same positional argument, `from_file` repeats the constructor, and reading pairs `from_midi` with writing `dumps_midi`. Plan, keeping the shape of pretty_midi and mido (construct from a path, write with a method), which is also what users and agents expect:
  1. `Score(path, *, ttype=Tick, format=None)` reads a file, choosing the format by extension unless `format` names it, and accepts a binary file object when `format` is given. `from_file`, `fmt` and the `Score(other, ttype)` conversion go; `other.to(ttype)` converts.
  2. In memory, each format has one pair, `Score.from_midi(data)`/`score.to_midi()` and `Score.from_abc(text)`/`score.to_abc()`; `dumps_midi` and `dumps_abc` go. A function named after a format takes or returns the encoded form, `bytes` or `str`. A conversion to the objects of another layer belongs to that object's class, as `MidiFile.from_score` does in the [MIDI message layer](#features), so `to_midi` still returns bytes when that layer arrives.
  3. Options of one format are keywords of its `from_` function only, never of the constructor; in C++ they are an options struct. Every `from_midi` option controls how the `Score` is built, so the MIDI message layer takes the same keywords on `MidiFile.to_score`; parsing the bytes has no options, and a malformed file always raises. `sanitize_data` becomes `invalid_data_bytes`, `"raise"` (the default) or `"clamp"`. The old name says neither which data nor what happens to it, and the option covers only data bytes above 127, not other malformed input (`tests/test_malformed_midi.py` raises with it set). `strict` would promise the same breadth, and mido's name for the option, `clip`, collides with `Score.clip`.
  4. The C++ core has the same names, `Score<T>::from_midi(span)` and `to_midi() const`, and one free function that reads a path by format, called by the binding's constructor.

  Open: whether an empty score keeps `Score(960)` or requires `Score(ticks_per_quarter=960)`; a path and an integer are distinguishable by type, so the keyword only makes the call read better. Whether `dump_midi(path)` and `dump_abc(path)` become one `score.dump(path, *, format=None)` that chooses by extension, which keeps one write method as formats are added but renames the most common write call.
- **Per-unit classes.** `symusic.Score` is an instance of `ScoreFactory` (`python/symusic/factory.py`, about 670 lines with a hand-written factory per type), not a class: `isinstance` works through `__instancecheck__`, but annotations, `match`, `issubclass`, `help()` and completion do not, so annotations need `symusic.types.Score`. The same concept has four names (the factory, `symusic.core.ScoreTick`, a generic placeholder in `core.pyi` that raises `TypeError` when instantiated, and the `symusic.types` alias), and users meet the per-unit class in `type()`, `repr`, errors and pickles. The factory also checks that the path is a file, validates `ticks_per_quarter` and merges `fmt` with `format`, and `ttype` takes a string or an object, so a type checker cannot infer the result. Decided, following NumPy (one `ndarray`, with the element type as the attribute `dtype` and the parameter of `NDArray[...]`):
  1. One Python class per concept: `Score`, `Track`, each event and each event list. The time unit is the attribute `ttype` and the generic parameter (`Score[Second]`); `Tick`, `Quarter` and `Second` are marker classes used for both, passed as `ttype=Second` with `Tick` as the default. The name stays `ttype`, as in 0.6 and in the C++ concept `TType`; `unit` already names the scalar type (`T::unit`) in C++. `s.to(Second)` returns a `Score`, and inserting an event of another unit raises `ValueError`.
  2. The binding holds a `std::variant` of the three core instantiations (`symusic::py::Score` over `Score<Tick, SharedStorage>`, ...) and binds each method once through one helper that visits the variant. The core is unchanged. Unit-dependent arguments, such as a `shift_time` offset, are converted per unit with the checked helpers.
  3. nanobind's stub generator writes the stubs from the one bound class per concept. A single runtime function cannot state that a type depends on the unit, so one hand-written pattern file, passed through `nanobind_add_stub(... PATTERN_FILE ...)`, replaces those members: overloads on `self` (`self: Score[Tick]`) for unit-dependent methods, and a generic descriptor for unit-dependent fields, so that `Note[Tick].time` is `int` and the other units give `float`. Its queries are regular expressions, so one rule covers a field in every event.
  4. `factory.py`, the `CoreClasses` dispatch, the placeholders, `symusic.types`, `scripts/lift_generic_stubs.py` with `cmake/LiftStubs.cmake.in`, string units and the `Score(other)` conversion go (see [file I/O names](#07-api)); the file and `ticks_per_quarter` checks move into the core.

  Gate: before the rewrite, a prototype with `Note`, its list and `Score`, built with the released nanobind and without patching any object at run time, must type field access correctly under both mypy and pyright, and a benchmark must show the cost of the variant dispatch on attribute access and iteration. If the typing does not hold, fall back to a real generic base class per concept whose `__new__` returns the per-unit class, with the per-unit classes registered as its virtual subclasses.
- **Field ranges.** Setters and constructors accept values outside the meaning of a field: `pitch=-5`, a negative `duration`, `TimeSignature(0, 3, 5)` with a denominator that is not a power of two, `KeySignature(0, 20, 7)` (shown as `degree=88`). A value outside the C++ type, such as `pitch=200`, raises `TypeError` from nanobind instead of `ValueError`. Define the valid range of each field in the field descriptions, decide whether constructors and setters or only writers check it, and raise `ValueError`.
- **Hashing.** Events, tracks and scores compare by value but hash by identity, so two equal notes have different hashes, which breaks the contract of `set` and `dict`. Make the mutable types unhashable, as `list` is.
- **Sequence protocol.** Event and track lists are not `collections.abc.MutableSequence` and lack `index` and `reverse`, which pyvec implements; the list `__copy__` takes a `deep` argument that the copy protocol never passes. Complete the protocol and register the lists as `MutableSequence`.
- **File errors.** A missing input file raises `ValueError` (from the factory), and other I/O failures raise `RuntimeError`. Raise `FileNotFoundError` and other `OSError` subclasses, as the [error rules](docs/development/conventions.md#errors) state.
- **NumPy names.** Lists export with `numpy()` but import with `from_numpy`, whose arguments are positional and named `arg0`, `arg1`, ... in the stubs. Name the pair `to_numpy`/`from_numpy`, with keyword arguments named after the fields and derived from the [field descriptions](#architecture).
- **Key signature mode.** `KeySignature.tonality` is an integer whose valid values are 0 (major) and 1 (minor). Use a `bool` or an enum.
- **Audio API.** `Synthesizer()` without a path downloads MuseScore General (about 38 MB) inside the constructor. `render` returns prestosynth's Eigen array through nanobind's Eigen caster, so its shape is not part of any documented contract, `quality` is an untyped integer, and `dump_wav(path, data, sample_rate, use_int16)` is a module-level function. With [FluidSynth](#features): require a SoundFont path, with the download in `symusic.soundfont` only; return a typed NumPy array with a documented shape; decide whether `dump_wav` stays.
- **Runtime discovery.** Users and agents that distrust the guide check the API at run time with `help()`, `dir()` and `__doc__`. Today `help(symusic.Score)` describes `ScoreFactory`, which [per-unit classes](#07-api) fixes. The first line of each nanobind docstring is the signature rendered from the C++ types, and it is the only runtime signature: `inspect.signature` raises `ValueError` on compiled methods, because nanobind functions carry no `__signature__`, and adding one would take a nanobind change or patching objects at import, neither of which symusic does. Add a test that the docstring of every public callable starts with its signature and names no C++ type, and correct wrong lines with `nb::sig`.
- **Public surface.** `symusic.core`, `symusic.factory` and `symusic.types` are importable and documented by their stubs. Make the top-level `symusic` the only public module and rename `core` to `_core`; pickles do not cross versions, so the rename breaks nothing that is supported.
- **Pedals.** MIDI read keeps every control change 64 in `controls` and also derives `pedals` from it (on at value 64 or above, off below, per channel; `src/io/midi.cpp`), while MIDI write ignores `pedals`. The same information has two representations, and editing `pedals` has no effect on the written file. Decide which one is the authority: derive pedals from `controls` on request, or store pedals and write them as control change 64.
- **SoundFonts.** `Soundfont.path()` downloads when the file is missing or fails verification, and every call reads the whole file into memory to hash it (`python/symusic/soundfont.py`). Built-in fonts are static methods with `PascalCase` names (`BuiltInSF3.MuseScoreGeneral()`), the hash field is `hash_`, and `pySmartDL` is a runtime dependency used only for this download. Separate locating, verifying and downloading; cache the verification; download to a temporary file in the target directory and rename it on success; reconsider the dependency.
- **Temporary files for ABC.** Each ABC call writes its input or output through a new directory under the system temporary directory (`ScopedTempDir` in `py_src/utils/process_runner.cpp`). `from_abc(str)` writes the text to one temporary directory and `from_abc_file` creates a second one; on Windows input and output files are copied through it as well. The tool paths reach the binding through the process environment variables `SYMUSIC_ABC2MIDI` and `SYMUSIC_MIDI2ABC`, which `symusic.factory` sets at import and child processes inherit. The `T:` line of exported ABC names the temporary file (see [ABC output](#behavior-defects)). Pass the tool paths as arguments, and keep one temporary directory per call.

## Toolchain compatibility

Workarounds and unsupported configurations with current toolchains.

- **Compiler floor.** `CONTRIBUTING.md` promises GCC 11+, Clang 15+ or MSVC 2022, and no CI job builds with GCC 11 or Clang 15. The wheels use GCC 14.2 (manylinux_2_28 and musllinux_1_2), AppleClang 17.0 with macOS deployment target 13.0, and MSVC 19.44 (x86) to 19.52 (arm64). Decided for 0.7: promise only what CI builds. Steps:
  1. A compile probe of the C++20 features the 0.7 code wants (such as `<format>`, ranges algorithms and views, `std::to_chars` for floating point), built by every wheel toolchain and against the macOS deployment target, decides the subset recorded in the [conventions](docs/development/conventions.md#standard-and-toolchain).
  2. State the oldest compiler each CI job pins as the floor in `CONTRIBUTING.md`, so the promise stays tested.

- **CMake 4.** `CMAKE_POLICY_VERSION_MINIMUM` in `CMakeLists.txt` and `pyproject.toml` exists because CMake 4 rejects projects declaring a minimum below 3.5. The direct submodules all declare 3.8 or later; the remaining offender is `gcem` (3.1) nested in `prestosynth`, whose upstream has since updated `gcem` and `libsamplerate`. Updating `prestosynth` should let the setting go.
- **Free-threaded Python.** Importing the extension on `3.13t`/`3.14t` re-enables the GIL with a `RuntimeWarning`. Supporting it requires declaring free-threading support in the module and auditing shared state.
- **nanobind `<cstdio>` workaround.** `py_src/CMakeLists.txt` force-includes `<cstdio>` because nanobind v3.1.0 omits it, which breaks limited-API builds with libc++. Remove the workaround once nanobind tags a release containing upstream commit `942e75d`.
- **Cross-compiled release wheels.** Building release wheels by cross-compiling on Linux with [xclang](https://github.com/clice-io/xclang) is the planned packaging path. The [experimental wheel path](docs/development/ci.md#cross-compilation-experiment) is opt-in. Integrate verified targets into `release.yml`, retain native builders for interpreter/platform combinations the experiment does not cover, and extend that coverage before retiring those builders.
- **Sphinx 9.** `docs/requirements.txt` pins `sphinx==7.4.7` and `docutils<0.21`; Sphinx 9.2 supports Docutils 0.23. Check that myst-parser and Furo support the new versions, then raise the pins and keep the `-W` build passing.
- **Deprecated CMake option names.** `cmake/BuildOptions.cmake` still maps the pre-0.6.1 names (`BUILD_SYMUSIC_PY`, `ENABLE_LTO`, ...) to the `SYMUSIC_` options with a deprecation warning. Remove the aliases in the next minor release.

## Memory safety

- **Negative tick times in conversion and export.** `SecondTimeConverter` inserts a tempo at tick 0 in front of a tempo with a negative time, which leaves its boundary list unsorted, and `src/io/midi.cpp` passes `i32` times to `minimidi` as `uint32_t` without a sign check. Both come from reading the code; neither has a regression test.
- **Integer narrowing outside tick arithmetic.** Tick arithmetic is checked; other integers are not. MIDI write casts `ticks_per_quarter` (`i32`) to `u16` (`src/io/midi.cpp`), so a value above 65535 wraps and one above 32767 sets the SMPTE bit of the MIDI division field. `KeySignature.degree()` wraps through `u8` (see [behavior defects](#behavior-defects)). Audit every subtraction on an unsigned type and every narrowing cast in `src/`, `include/` and `py_src/`, and apply the [integer rule](docs/development/conventions.md#integers-and-time).
- **Pickles from another version.** Pickle state is raw `zpp_bits` output with no version marker (`src/io/zpp.cpp`). Bytes from another symusic version, such as between workers with different installs, fail only if they happen to overrun the buffer; a layout change of the same length loads as wrong values. Write a format version at the start of the state and raise `ValueError` naming the versions when it differs. Pickles are not compatible across versions; the check only makes the mismatch explicit.
- **Python tests under ASan.** CI runs the C++ tests with ASan and UBSan, but not pytest. A sanitized extension needs `LD_PRELOAD` of `libasan` and `libubsan` even at install time, because the build runs nanobind's stub generator, which imports the extension (without it the install fails with "ASan runtime does not come first"). Preloading for the whole `uv pip install` process exhausted resources and was killed. Untried: build the extension with `SYMUSIC_BUILD_PYTHON=ON` and `SYMUSIC_PYTHON_STUB` pointing at a stub from a normal build to skip generation, then run pytest with the preload and `ASAN_OPTIONS=detect_leaks=0`.

## Behavior defects

Found while checking the guide against the package. Each fix needs a test that fails without it.

- **Lyrics on a separate track.** MIDI import files a lyric under `meta.channel()` (`src/io/midi.cpp`), which is 15 for every meta event, so lyrics land in a track of their own instead of the track with the notes, and a written track with notes and lyrics reads back as two tracks. Decide where lyrics belong (the MIDI track's first note channel, or a per-MIDI-track lyric list) and keep the round trip stable.
- **`trim` modes.** `trim_inplace` (`include/symusic/ops.h`) compares `start_mode` and `end_mode` with `"remove"` and `"truncate"`; any other string keeps the events that cross that boundary without cutting them. Reject unknown modes with `ValueError`, or replace the strings with an enum.
- **`adjust_time` with repeated anchors.** Equal consecutive values in `original_times` pass `check_times`; the segment between them gets an infinite or NaN scale factor (`adjust_time_inplace_inner` in `include/symusic/ops.h`), and casting the scaled time to an integer is undefined behavior. Require strictly increasing original times.
- **`KeySignature.degree()` for flat keys.** `(key * 5) % 12` is negative for negative `key`, and the `u8` result wraps, so the repr shows `degree=251` for F major (`key=-1`). Use a non-negative modulo.
- **`Score.trim`.** `trim` is bound for tracks only; the C++ score overload has no binding.
- **`Note.ent_time`.** A misspelled duplicate of `end()` is bound in `py_src/bindings/events/event_bindings.h`. Deprecate and remove it.
- **`to()` in the stubs.** `Score.to`, `Track.to` and the event `to` return `object` in `core.pyi`; type them by the target unit.
- **ABC output.** `dumps_abc` prints "calling midi2abc" to stdout, and the `T:` line of the result names the temporary MIDI file. Silence the message and write the score's title, or none.
- **SoundFont download error.** The `ConnectionError` raised by `Soundfont.download` formats the bound method `self.path` instead of the file path.
- **ABC tune selection.** ABC import reads only the first tune of a file. Accept the `X:` number of the tune to read.

## Architecture

Changes that reduce the number of places one change must touch.

- **One field list per event.** Each event's fields are written out separately in `include/symusic/event.h`, `include/symusic/repr.h`, `include/symusic/soa.h`, `py_src/bindings/events/event_bindings.h`, `py_src/utils/python_helpers.h` and `python/symusic/factory.py`, while pickle copies the raw struct (`src/io/zpp.cpp`). Adding or retyping a field means editing all of them consistently. Describe each event's members once, as a hand-written `constexpr` tuple of name and member-pointer pairs per event (Boost.PFR needs recent compilers for names, and C++26 reflection is not available), and derive repr, the structure-of-arrays and NumPy fields, the binding properties and the factory signatures from that description, keeping old pickles loadable.
- **Example-only headers.** `include/argparse.h` (about 2,200 lines, excluded from `clice lint`) sits in the core's public include directory but only `examples/cpp/` uses it. Move it under `examples/` or replace it with a pinned release.
- **Core independent of Python.** `Score` and `Track` store every event list as `shared<pyvec<E>>` (`include/symusic/score.h`, `track.h`; also `soa.h`, `ops.h`, `conversion.h`), and the core target links pyvec publicly, so a C++ user gets the container and shared ownership that only Python reference stability needs, and the `ScoreNative`/`TrackNative` copies exist beside them. Make the storage a template parameter, `Track<T, S>` and `Score<T, S>`, so that every algorithm is written once:
  1. A storage policy owns everything container-specific: the list type of each field, the handle type of a track, `get` (the list behind a field), `adopt` (take a filled `vec<E>` by move), `erase_if` and `sort`. The core defines `ValueStorage` (`vec<E>`, tracks by value) as the default, so C++ users write `Score<Tick>` and get value semantics. `py_src/` defines `symusic::py::SharedStorage` (`shared<pyvec<E>>`, tracks as `shared<Track>`), the only code that names pyvec. pyvec's `sort` reorders its pointer array, so Python references stay valid.
  2. Algorithms take `S` as a template parameter and reach containers only through it. Code that only iterates and edits elements (time shifts, conversion, piano rolls) needs no change, because both containers are random-access ranges of events.
  3. Code that builds a new list, including the parsers, `clip`, `to` and `resample`, fills a `vec<E>` and passes it to `S::adopt`. For pyvec, `adopt` moves the vector in as one chunk (`pyvec(std::vector<T>&&)` exists), so no list is built by appending to a pyvec.
  4. `ScoreNative`/`TrackNative` become `Score<T, ValueStorage>`/`Track<T, ValueStorage>`, and `to_shared` becomes one conversion that adopts every field. MIDI write and pickle read either storage directly instead of copying through `to_native`.
  5. Template definitions move to `include/symusic/detail/*_impl.h`. `src/` instantiates them for `ValueStorage` and each unit, `py_src/` for `SharedStorage` and each unit, so each combination compiles once and other translation units see only declarations.

  The core target then stops linking pyvec, and an install and export rule lets C++ projects use it through `find_package(symusic)`. Type-erased containers were rejected because they add an indirect call per element access on the hot loops. This changes the C++ API and belongs to 0.7.
- **MIDI semantics in minimidi.** minimidi parses and writes messages only; the meaning the MIDI standard gives them is implemented in symusic (`src/io/midi.cpp`): pairing note-on and note-off into notes, velocity 0 as note-off, decoding tempo, time and key signature and other meta events, and on write splitting notes back into ordered events. Without that layer minimidi cannot be tested or used on its own at note level. The boundary: a rule that every MIDI reader must apply the same way belongs in minimidi; a choice symusic makes belongs in symusic (splitting tracks by channel and program, deriving [pedals](#07-api), the `Score` model, validation of the result). minimidi exposes the note layer through a sink concept for reading and a source concept for writing, tested in minimidi with a recording sink that stays in its tests rather than becoming a second public score model. Steps:
  1. In symusic, without behavior change, split `src/io/midi.cpp` into the note layer and a `Score` builder that implements the sink. The builder is the single entry for every importer: it sorts, validates and groups events into tracks by a key the importer supplies.
  2. Move the note layer into minimidi with its own tests, tag a release and pin it.
  3. Do the same for writing through the source concept.
- **minimidi branch.** `.gitmodules` names branch `template-container` for `3rdparty/minimidi`, but the pinned commit is on `main`. Make the declared branch match the pin.

## Code cleanup

Existing code that breaks the [code conventions](docs/development/conventions.md). Each item is a `refactor` without behavior change unless it says otherwise; the [architecture](#architecture) items above remove the duplication that several of these macros exist for.

- **Macro code generation in the core.** `REPEAT_ON` from the vendored `3rdparty/MetaMacro.h` instantiates templates per unit and generates per-field code in `include/symusic/repr.h`, `include/symusic/soa.h`, `include/symusic/io/midi.h`, `src/event.cpp`, `src/track.cpp`, `src/score.cpp`, `src/repr.cpp` and `src/io/zpp.cpp`. `BASIC_TIMESTAMP_METHODS`, `COMPILER_DEFAULT_METHODS` and `POINTER_METHODS` write class bodies in `include/symusic/event.h`; `PIANOROLL_MODES` is an X-macro in `include/symusic/pianoroll.h`; `KEY` in `include/symusic/ops.h` is never undefined; `ERROR_PARSE_DUMPS` guards with `static_assert(true, ...)`, which never fires. Templates also carry flags that are not compile-time choices: `parse<DataFormat F>`/`dumps<DataFormat F>` on every event, track and score, with `MusicXML`, `ALPACA` and `CEREAL` declared but not implemented, so misuse fails at link time; `template<bool check_times>` on `adjust_time`; the `sanitize_data` flag of `parse`. Replace each by what it stands for:
  1. Explicit instantiations are written out, one line per class and unit (`template struct Track<Tick>;`), in one instantiation file per area, instead of `REPEAT_ON`. The language cannot loop over explicit instantiations, and a class instantiation covers all its non-template members.
  2. Events become aggregates over `TimeStamp<T>`. Delete the defaulted special members (implicit), the repeated `ttype`/`unit` (inherited), and `operator->`/`operator*` returning `this`, which let generic code treat an event like a `shared` pointer; [storage](#architecture) access replaces them. `copy`/`deepcopy` move to the binding's copy helper, and the eight `shift_time` members become one function template over `TimeEvent`.
  3. `KEY` becomes a ranges projection.
  4. The [field descriptions](#architecture) replace the per-field code in `soa.h`, `repr` and `zpp.cpp`, and `to_string` with it.
  5. With the [0.7](#07-api) I/O names and typed closed sets: format templates become named functions (`Score<T>::from_midi`/`to_midi`, the ABC pair, pickle `serialize`/`deserialize`), the run-time dispatch by path or format moves from the binding's `get_format` into one core function, and `MusicXML`, `ALPACA` and `CEREAL` go (MusicXML returns as [its own module](#features)); `PIANOROLL_MODES` becomes an enum bound with `nb::enum_` and, where names are needed, a `constexpr` table shared by all closed sets; `check_times` becomes a validating public function over an unchecked `detail` one, and `sanitize_data` becomes the `invalid_data_bytes` field of the MIDI read options. Today minimidi clamps while parsing (a `MidiFileView` with its sanitize flag reads into an owning message container and clamps it in place), and the builder only skips its range checks. Afterwards the parse keeps the raw bytes and the builder clamps each field, before a pitch bend combines its two bytes, so that the [MIDI message layer](#features) shows the file as written.

  Steps 1 to 3 are independent refactors. Delete `MetaMacro.h` when the last use is gone.
- **Header hygiene.** Headers carry both `#pragma once` and an `#ifndef` guard, some with wrong names (`LIBSYMUSIC_TRACK_HSCORE_H` in `score.h`, `SYNTH_H` in `synth.h`). `event.h` includes `"iostream"` with quotes; about 40 `typedef`s, reserved identifiers (`_Ty` in `mtype.h`, `__COUNT` in the macros), camelCase names (`sfPath`, `timeDim`, `getBanks`) and comments that contradict the signature ("inplace sort, and return self reference" on `void` functions in `track.h` and `score.h`) remain.
- **Namespaces.** Core internals use both `symusic::details` and `symusic::ops::details`; binding code is split across `pyutils` and `symusic`, with docstrings in five more `*_docstrings` namespaces.
- **Binding layer.** Every transformation repeats the copy-or-in-place lambda for each type (`py_src/bindings/score/score_bindings.h`, `track/track_bindings.h`, `events/event_bindings.h`). Signatures are assembled by hand with `fmt::format` into `nb::sig`. Bytes-to-span conversion and pickle state handling are written inline per class. The `RW_COPY`, `NDARR`, `TO_NUMPY` and `BIND_*` macros generate binding code. ABC file staging, format detection by extension (`get_format`) and the `from_file` dispatch are implemented in `score_bindings.h` instead of the core.

## Features

- **FluidSynth in place of prestosynth.** `Synthesizer` (`include/symusic/synth.h`) wraps prestosynth, and its C++ interface returns `psynth::AudioData`. The renderer passes only notes and bank selects (control change 0) to prestosynth (`src/synth.cpp`), so pitch bends, other control changes and pedals do not reach the audio. Replace it with FluidSynth:
  1. Put a backend boundary in the core: render a `Score<Second>` into a symusic-owned audio buffer, so the public C++ API no longer exposes prestosynth types.
  2. Implement the FluidSynth backend. Rendering is offline: configure the sample rate, load the SoundFont, send program, note, control-change and pitch-bend events in time order and pull blocks with `fluid_synth_write_float`.
  3. Remove prestosynth, with the Eigen, gcem, libsamplerate and mio copies nested in it and the binding's Eigen caster (`nanobind/eigen/dense.h`). That also removes the [CMake 4](#toolchain-compatibility) workaround, which exists for the `gcem` copy nested in prestosynth.
  4. Distribution: FluidSynth is LGPL-2.1, so the extension loads `libfluidsynth` dynamically at run time and the base wheel does not contain it. `pip install symusic[fluidsynth]` installs the rendering dependencies, including a package that provides `libfluidsynth` for every wheel platform; without it, creating a `Synthesizer` raises an error that names the extra. Open: which package provides the library (an existing wheel on PyPI or a companion wheel built by symusic, with its dependencies such as glib), whether a system or user-supplied library is also accepted, the minimum FluidSynth version, reverb and chorus defaults, and how the `quality` argument maps to FluidSynth settings. Test length, channel count and non-silent output, and that pitch bends and control changes change the result, rather than sample equality.
- **MusicXML.** After 0.7. symusic has no MusicXML support; `DataFormat::MusicXML` in `include/symusic/io/iodef.h` is declared but not implemented. The module is `symusic::musicxml` with its own header, namespace and CMake target (see the [namespace rules](docs/development/conventions.md#namespaces-and-headers)). It reads into `Score<Tick>`, one track per part, by rendering the notation into performance events and writing them through the `Score` builder from [MIDI semantics in minimidi](#architecture); the layers are described in the [architecture](docs/design/architecture.md#score-and-file-formats). In Python it adds `Score.from_musicxml`/`to_musicxml` and the `.musicxml` and `.mxl` extensions. Plan:
  1. Choose the parser. [mx](https://github.com/webern/mx) (MIT, C++20, tagged releases, latest v0.7.1, under active development: 0.7.0 replaced `DocumentManager`) parses into `mx::api`, a notation model timed in ticks per quarter. Built at v0.7.1 with GCC on Linux, its libraries are 535 translation units and about 30 CPU-minutes, and they add about 10 MB stripped even to a binary that only imports, more than the whole extension today (6.5 MB). mx does not read `.mxl`, and `mx::api` keeps only the first transposition of a part. A performance import needs a small part of the schema (part list and MIDI instruments, attributes, notes, backup and forward, directions and sound, barlines), which an importer on pugixml, a single translation unit, can read directly and keep in the base wheel. The rendering in step 2 is the same work with either parser, and the module boundary hides the parser, so the choice can be revised later. mx's test corpus serves as regression input in both cases, after checking the license of each file.
  2. Import. Decide and test each mapping: tied notes merge into one note; grace notes; repeats and jumps (written order or unrolled); voices and staves inside a part; dynamics to velocity; tempo from `<sound tempo>` and metronome marks; transposing instruments (sounding pitch), including changes inside a part; unpitched percussion. Read compressed `.mxl` with a zip reader.
  3. Export after import is stable. MusicXML needs notation that symusic does not model (measures, voices, ties across bar lines, note types), so export requires quantization and notation inference; scope it separately.
- **MIDI message layer.** After 0.7. `Score` is a performance model and drops what a MIDI file holds beyond it: SysEx, unknown meta events, the order and division of tracks, the channel of each message. A read-only view of the messages, in `symusic.midi`, serves inspecting a parse, reading that data, and tokenizers that work in file order. It is the parse layer of MIDI, not a second score model; the note layer from [MIDI semantics in minimidi](#architecture) stays internal. Plan:
  1. Types: `MidiFile` (format, division, tracks), `MidiTrack`, one immutable class per channel message (`NoteOn`, `NoteOff`, `ControlChange`, `ProgramChange`, `PitchBend`, `ChannelPressure`, `PolyPressure`), `SysEx` with its bytes, and one `Meta` with a `MetaType` enum and the raw bytes. Meta events stay undecoded, since decoding tempo and signatures is the note layer's job, and no name clashes with the `Score` events. Times are absolute ticks in file order. The C++ types come from minimidi.
  2. `MidiTrack.to_numpy()` returns columns (time, kind, channel, data1, data2), as the event lists do; one Python object per message is what makes mido slow on large data sets.
  3. `MidiFile.from_bytes(data)`, `file.to_bytes()`, `MidiFile.from_score(score)` and `file.to_score(*, ttype=Tick, ...)` connect it to bytes and to `Score`; `Score` itself does not refer to `MidiFile` ([file I/O names](#07-api)). `to_score` takes the same options as `Score.from_midi`. `Score.from_midi` keeps its direct path, and tests check that `Score.from_midi(data, **options)` equals `MidiFile.from_bytes(data).to_score(**options)` and that `score.to_midi()` equals `MidiFile.from_score(score).to_bytes()` byte for byte, which requires a deterministic writer. `MidiFile` keeps the raw bytes, including data bytes above 127, and written back to bytes it round-trips, apart from running status.
  4. Editing messages waits for a use case.
- **ABC through abcmidi.** ABC import and export build `abc2midi` and `midi2abc` as separate executables from the upstream sources (wrapper translation units in `cmake/abcmidi/`), ship them in the wheel and run them through temporary files (`py_src/utils/process_runner.cpp`). They stay the only ABC implementation and stay out of process:
  - The ABC that users convert follows `abc2midi`'s behavior, not only the ABC 2.1 standard: `%%MIDI` directives such as `gchord`, `drum`, `drone` and `beat`, how grace notes take time, voice overlay and its recovery from malformed input. A native parser would differ from it in each of these places, and keeping two implementations in agreement is a permanent cost.
  - abcmidi is GPL-2.0-or-later and symusic is MIT. Under the FSF's reading of the GPL, linking it into the extension, statically or dynamically, makes the combination a derivative work. A separate GPL package could link it, but abcmidi is written as a program, with global state and `exit()` on errors, so in-process use needs a maintained fork.

  Work on the current integration:
  1. `abc2midi` exits with status 1 after any reported error, including errors it recovers from, and `event_fatal_error` also exits with 1, so symusic rejects tunes that `abc2midi` converts: a stray `]` inside a chord or a `\` in the middle of a line still writes a MIDI file, while a missing key signature writes none. Confirm that a fatal exit never leaves a partial file, then accept conversions that produced one and report the messages as warnings.
  2. Capture the converters' messages, which `abc2midi` prints on stdout, instead of passing them to the terminal, and include them in the exception, which now names only the command and the exit code.
