# 0.6 → 0.7 Migration Reference

All **73 changes** (57 Python + 16 C++ Core). Rows marked **Deprecated** are the most used 0.6 forms: they still work in 0.7 with a `FutureWarning` that names the replacement, and 0.8 removes them. Every other old form is removed in 0.7.

> [!TIP]
> For interactive filtering and search, see the live preview site: https://symusic-v07-lyk.edge.randallflare.com/migration

## Python 0.6 → 0.7 (57 Changes)

| Severity | Category | 0.6 | 0.7 | Notes |
|---|---|---|---|---|
| Breaking | Imports & Types | `from symusic.core import NoteTick` | `from symusic import EventList, Note, Tick` | `symusic.core` becomes private `symusic._core`; `symusic.factory` and `symusic.types` are removed. Annotate with `Note[Tick]` and `EventList[Note[Tick]]`. |
| Breaking | Imports & Types | `ttype="tick"`<br>`TimeUnit.tick / TimeUnit.from_str(s)` | `ttype=Tick` | `ttype` is keyword-only and takes non-instantiable marker classes `Tick`, `Quarter`, or `Second`. Map config strings via `{"tick": Tick, "quarter": Quarter, "second": Second}[s]`. Calling `Score[Second]()` raises `TypeError`. |
| Breaking | Constructors & I/O | `Score(960)`<br>`Score.from_tpq(960)` | `Score(tpq=960)` | `Score(...)` constructs purely in memory with keyword-only arguments (defaults to `tpq=960`, `ttype=Tick`). |
| **Deprecated** | Constructors & I/O | `Score(path)`<br>`Score(path, Second)` | `Score.from_file(path)`<br>`Score.from_file(path, ttype=Second)` | Deprecated, removed in 0.8: `Score(path)` and `Score(path, ttype)` still read the file with a `FutureWarning`; `ttype` must be a marker class, since unit strings get no shim, and any other argument raises `TypeError`. The stub marks this overload with `@deprecated` (PEP 702), so type checkers warn rather than fail. From 0.8 the constructor takes only keywords, which ends the guessing between a file path, a resolution and a score to copy or convert. |
| Renamed | Constructors & I/O | `Score.from_file(path, fmt=..., sanitize_data=True)` | `Score.from_file(path, format=..., strict=False)` | `fmt` -> `format`; `strict=True` (default) rejects MIDI data bytes > 127, while `strict=False` clamps them to 127. Binary streams require explicit `format`. |
| **Silent trap** | Constructors & I/O | `Score(other)`<br>`Score.from_other(other, ttype)` | `other.to(Tick)  # or other.copy()`<br>`other.to(ttype)` | Silent 0.6 quirk: `Score(other)` converted `Quarter`/`Second` scores to `Tick` by default. Use `other.to(ttype)` to convert or `other.copy()` to preserve `ttype`. |
| Renamed | Constructors & I/O | `Score.from_midi(data, sanitize_data=True)`<br>`Score.from_abc(abc=text)` | `Score.from_midi(data, strict=False)`<br>`Score.from_abc(text)` | All readers (`from_file`, `from_midi`, `from_abc`) take `strict=True` by default; pass `strict=False` to clamp out-of-range MIDI data bytes. |
| Renamed | Constructors & I/O | `score.dumps_midi()`<br>`score.dumps_abc()` | `score.to_midi()`<br>`score.to_abc()` | Symmetric with `Score.from_midi()` and `Score.from_abc()`. |
| **Deprecated** | Constructors & I/O | `score.dump_midi(path)`<br>`score.dump_abc(path)` | `score.to_file(path, format="midi")`<br>`score.to_file(path, format="abc")` | Deprecated, removed in 0.8: both still write their own format, whatever the extension, with a `FutureWarning`; `dump_abc` no longer takes `warn`. `to_file` is the one writer for paths and binary streams. Without `format` it picks the format from the extension, so `format=` is needed only to match the old methods on a path with another extension. Binary streams require explicit `format`, remain caller-closed, and handle short writes. |
| **Deprecated** | Constructors & I/O | `score.ticks_per_quarter`<br>`score.tpq = 480` | `score.tpq`<br>`score = score.resample(480)` | Deprecated, removed in 0.8: reading `score.ticks_per_quarter` still works with a `FutureWarning`; `tpq` is the single canonical resolution name. Assigning either name raises `AttributeError` already in 0.7, since the resolution is read-only after construction. Use `resample(480)` to change resolution while preserving musical positions (rescaling tick times), or build `Score(tpq=480, tracks=score.tracks, ...)` when deliberately reinterpreting raw tick coordinates without scaling. Retained on `Quarter`/`Second` scores as metadata for `.to(Tick)` and MIDI export (`1..32767`). |
| Renamed | Events & Pedals | `score.note_num()`<br>`track.note_num()` | `score.note_count()`<br>`len(track.notes)` | `Track` drops `note_num()` in favor of standard `len(track.notes)`; `Score` spells it out as `note_count()`. |
| Renamed | Operations & CQS | `score.get_beats(start_time=0)`<br>`score.get_downbeats(start_time=0)` | `score.beats(start=0)`<br>`score.downbeats(start=0)` | Drops redundant `get_` prefix and shortens `start_time` to `start`. |
| **Silent trap** | Events & Pedals | `x.empty()` | `x.is_empty()` | Consistent predicate naming across `Score`, `Track`, and `EventList`. For lists, `not notes` also works. Silent change: 0.6 `Score.empty()` was false for a score holding a track without events, while 0.7 `is_empty()` ignores such tracks ([bounds and emptiness](./semantics.md#bounds-and-emptiness)). Test `not score.tracks` for a score with no tracks. |
| Renamed | Operations & CQS | `score.to(ttype, min_dur=...)` | `score.to(ttype, min_duration=...)` | `min_duration` is spelled out and keyword-only. A negative value raises `ValueError`; 0.6 `to()` treated it as 0. |
| Breaking | Operations & CQS | `score.resample(tpq=480, min_dur=...)` | `score.resample(480, min_duration=...)` | Returns `Score[Tick]` quantized directly to the target grid in one step (avoiding double rounding on `Quarter`/`Second` scores); `min_duration` is keyword-only. |
| Breaking | Operations & CQS | `notes.sort(key, True)` | `notes.sort(key=key, reverse=True)` | `key` and `reverse` are keyword-only on lists. `Score.sort()` and `Track.sort()` sort all contained event lists by default keys while keeping `Score.tracks` in order. |
| **Silent trap** | Operations & CQS | `y = x.shift_pitch(2)`<br>`x.shift_time(d, inplace=False)` | `y = x.copy(); y.shift_pitch(2)`<br>`y = x.copy(); y.shift_time(d)` | Silent trap: `sort`, `shift_time`, `shift_pitch`, and `shift_velocity` now mutate in place and return `None`. Writing `y = x.shift_pitch(2)` mutates `x` and sets `y = None`! |
| **Silent trap** | Operations & CQS | `x.clip(..., inplace=True)`<br>`x.adjust_time(...)` | `x = x.clip(...)`<br>`x = x.adjust_time(...)` | Element-dropping transforms (`clip`, `adjust_time`, `filtered`) always return a new object and leave the source unchanged; the list `filtered` returns holds the source's elements. Ignoring the return value is a silent no-op. |
| Renamed | Operations & CQS | `x.clip(start, end, clip_end=True)` | `x.clip(start, end, tail="drop")` | `head` and `tail` decide what happens to a note sticking out before `start` or after `end`: `"drop"`, `"cut"` or `"keep"`. The defaults (`head="drop"`, `tail="keep"`) keep 0.6 `clip(start, end)` unchanged. With `tail="drop"`, a zero-duration note exactly at `end` is now dropped, which `clip_end=True` kept, because the window is `[start, end)`. `start` and `end` may now be passed by keyword. See [clip](./semantics.md#clip). |
| Breaking | Operations & CQS | `track.trim(start, end)`<br>`track.trim(start, end, end_mode="truncate")`<br>`track.trim(start, end, start_mode="truncate", end_mode="truncate")` | `track.clip(start, end, tail="drop")`<br>`track.clip(start, end, tail="cut")`<br>`track.clip(start, end, head="cut", tail="cut")` | `trim` merges into `clip`: `start_mode` becomes `head` and `end_mode` becomes `tail`, with `"remove"`, `"truncate"` and `"retain"` renamed to `"drop"`, `"cut"` and `"keep"`. The defaults differ: `trim` dropped at both ends, `clip` keeps tails. `min_overlap` is removed. With `head="cut", tail="cut"` every kept duration is the note's overlap with the window, so filter the result by `duration`; for modes that keep a side, filter the source by overlap first, as in `src.notes = src.notes.filtered(lambda n: min(n.end, end) - max(n.time, start) >= k)` on a copy `src`. A note starting exactly at `end` is now always dropped, which `end_mode="retain"` kept. `clip` also exists on `Score`, where 0.6 `trim` was not bound. |
| Breaking | Operations & CQS | `notes.filter(f)`<br>`tracks.filter(f, inplace=True)` | `track.notes = track.notes.filtered(f)`<br>`score.tracks = score.tracks.filtered(f)` | Renamed to `filtered(f)` on `EventList` and `TrackList`. It returns a new list holding the same elements that `f` accepts, like `[n for n in notes if f(n)]`; the elements are not copied. To mutate in place through aliases, use `notes[:] = notes.filtered(f)`. |
| Breaking | Operations & CQS | `x.copy(deep=False)`<br>`notes.copy()` | `copy.copy(x)`<br>`notes.copy()` | A list's `copy()` is shallow, as `list.copy()` is. `score.copy()`, `track.copy()` and `note.copy()` are deep and equal `copy.deepcopy(x)`, which keeps aliases inside the copied graph (`[n, n]` copies to `[m, m]`). The `deep=` argument is removed; `copy.copy(x)` gives a shallow copy. Copy constructors (`Score(other)`, `Note(other)`) are removed. See [copies and references](./python-api.md#copies-and-references). |
| **Silent trap** | Operations & CQS | `copy.copy(notes)`<br>`copy.deepcopy([score, track])` | `copy.deepcopy(notes)`<br>`copy.deepcopy([score, track])` | 0.6 `copy.copy` of an `EventList` or `TrackList` copied its elements; 0.7 makes it shallow, as for `list`, so editing an element of the copy edits the source. Use `copy.deepcopy` for independent elements. `copy.deepcopy` now uses the caller's memo: when `track` belongs to `score`, the copied list holds the copied score and that score's own copied track, where 0.6 made two unrelated copies. |
| Breaking | Events & Pedals | `Track.empty(ttype)`<br>`Track(..., pedals=...)` | `Track(ttype=Tick, controls=[...])` | `Track(...)` replaces `Track.empty()`. Stored `pedals` are removed; encode sustain as CC64 `ControlChange` pairs in `controls`. |
| **Silent trap** | Events & Pedals | `track.pedals` | `track.pedals()` | Changed from a stored list to a method returning a detached tuple derived from CC64 in `track.controls`. Watch out: `clip` selects controls by timestamp, which can split boundary pedals. |
| **Silent trap** | Events & Pedals | `NoteTick(t, d, p)` | `Note(t, d, p)  # velocity=64` | Silent behavior change from old core bindings: omitted `velocity` now defaults to `64` (MIDI 1.0 recommended default `0x40`, matching `mido` and `muspy`) instead of `0`. |
| **Deprecated** | Events & Pedals | `Note.start / Pedal.start`<br>`note.ent_time()` | `note.time / pedal.time`<br>`note.end` | Deprecated, removed in 0.8: reading and assigning `start`, and calling `ent_time()`, still work with a `FutureWarning`. Removes the duplicate `start` alias of `time` and the misspelled `ent_time()` method; the `end` property stays. |
| Renamed | Events & Pedals | `TextMeta(time, text)` | `TextEvent(time, text)` | Renamed for clarity across lyrics and markers. Calling `to_numpy()` on `EventList[TextEvent[T]]` raises `TypeError`. |
| Renamed | Events & Pedals | `tempo.tempo`<br>`Tempo(t, qpm, mspq)` | `tempo.qpm`<br>`Tempo(t, qpm)  # or mspq=...` | Removes the duplicate `.tempo` alias in favor of `.qpm`; `.mspq` (microseconds per quarter, default `500_000`) stays unchanged. Passing both `qpm` and `mspq` raises `ValueError`; 0.6 used `qpm` and ignored `mspq`. `Tempo.__match_args__` is `("time", "qpm")`. |
| Breaking | Events & Pedals | `KeySignature(t, key, tonality)`<br>`ks.key / ks.tonality` | `KeySignature(t, fifths, minor)`<br>`ks.fifths / ks.minor: bool` | `key` held the number of sharps (positive) or flats (negative), `-7..7`; it is renamed `fifths`, as in MusicXML and muspy. Numeric `tonality` (0/1) becomes the boolean `minor`. The new read-only `ks.tonic` gives the tonic pitch class `0..11`; `ks.tonic + 12 * ks.minor` gives a 24-key index. |
| Renamed | NumPy & SoA | `notes.numpy()`<br>`Note.from_numpy(...)` | `notes.to_numpy()`<br>`EventList.from_numpy(Note, **cols)` | Numeric column dtypes are unchanged (`pitch` and `velocity` stay `int8`, so `np.diff` of `0..127` values cannot wrap); `tonality` (`uint8`) becomes `minor` (`bool`). Columns renamed: `key` -> `fifths`, `tonality` -> `minor` (`mspq` stays unchanged). |
| Breaking | Synthesis & SoundFont | `Synthesizer(sf_path=None, quality=...)` | `Synthesizer(path_to_sf2_or_sf3)`<br>`Synthesizer(download_soundfont(), interpolation="highest")` | FluidSynth 2.6.2+ replaces `prestosynth` inside the wheel. Requires a local SF2/SF3 path or one-click `download_soundfont()`; untyped `quality` is replaced by typed `interpolation` (`"none" \| "linear" \| "fourth_order" \| "mid" \| "high" \| "highest"`, default `"fourth_order"`). |
| **Silent trap** | Synthesis & SoundFont | `synth.render(score)`<br>`synth.render(score, False)` | `synth.render(score)`<br>`synth.render(score, channels=1)` | Silent shape trap: the output changes from `(channels, samples)` to float32 `(sample_frames, channels)`, stereo by default and `(sample_frames, 1)` for mono, so `audio[0]` is now the first frame rather than the left channel; `audio.T` gives the 0.6 layout. The output also sounds different: 0.6 played notes only, and 0.7 also plays controls, sustain and pitch bends. Options are keyword-only, so a positional `True` or `False` raises `TypeError`. `render()` also takes `tail_seconds` (moved from the constructor) and `sample_frames` for an exact length ([rendering](./semantics.md#rendering)). |
| Breaking | Synthesis & SoundFont | `symusic.dump_wav(path, audio, rate)` | `sf.write(path, audio, rate)`<br>`symusic.write_wav(path, audio, rate)` | `dump_wav` is removed. Use `soundfile.write` for multi-format output (WAV/FLAC/OGG/Opus/MP3 — natively accepts float32 `(frames, channels)`), or built-in zero-dependency `symusic.write_wav(path, audio, rate, *, encoding="pcm16")` for quick WAV debugging without extra packages (`use_int16` becomes `encoding="pcm16" \| "float32"`). Both take `(frames, channels)`, so an array kept from 0.6 needs `audio.T`. `soundfile` writes WAV as 16-bit PCM unless given `subtype="FLOAT"`. |

| Renamed | Events & Pedals | `note.empty()` | `note.is_silent()` | `Note.empty()` meant zero duration or zero velocity, unlike `is_empty()` on containers; the new name says what it tests. |
| **Silent trap** | Imports & Types | `{note}`<br>`cache[score] = ...` | `{id(note)}`<br>`cache[id(score)] = ...` | Events, tracks, scores and lists compare by value and are mutable, so they are unhashable (`__hash__ = None`, as for `list`). Using one in a `set` or as a `dict` key raises `TypeError`. Key by `id()` only while the object is alive, since Python reuses the id of a collected object: store the object with its value, as in `cache[id(score)] = (score, value)`. |
| Breaking | Imports & Types | `x.__use_count()` | — | The `__use_count` debugging method is removed from events, tracks, scores and lists. |
| **Silent trap** | Constructors & I/O | `pickle.loads(v06_score_bytes)` | `# In 0.6: score.dump_midi("tmp.mid")`<br>`# In 0.7: Score.from_file("tmp.mid")` | Pickles are for inter-process transport, not archival storage. 0.7 uses a private C++20 LE codec in `bindings/python/` with a versioned `SYMZ v3` header and rejects 0.6 payloads. | **Silent trap** | Imports & Types | `isinstance(x.ttype, Tick)`<br>`x.ttype == TimeUnit.tick`<br>`x.ttype.is_time_unit()` | `x.ttype is Tick` | `.ttype` now returns the non-instantiable marker class (`Tick`, `Quarter`, or `Second`) itself instead of an instance, and `is_time_unit()` is removed. Use `x.ttype is Tick` (or `== Tick`), test for a unit with `u in (Tick, Quarter, Second)`, and pass `x.ttype` directly as `ttype=x.ttype`. |

| Breaking | Synthesis & SoundFont | `Synthesizer(sf_path=p)`<br>`Synthesizer(p, 44100)` | `Synthesizer(soundfont=p)`<br>`Synthesizer(p, sample_rate=44100)` | `sf_path` is renamed to `soundfont`, and all options after `soundfont` (`sample_rate`, `polyphony`, `gain`, `interpolation`, `reverb`, `chorus`, `cpu_cores`) are keyword-only. Passing `sf_path=` or a positional `sample_rate` raises `TypeError`. `tail_seconds` is an option of `render()`. |
| **Silent trap** | Operations & CQS | `controls.sort()` | `controls.sort()` | The default key of `ControlChange` is `time` alone. 0.6 sorted by `(time, number, value)`, which reversed same-tick CC64 values `127, 0` to `0, 127` (leaving the pedal held) and reordered same-tick RPN/NRPN and Bank Select sequences (`CC101, CC100, CC6` -> `CC6, CC100, CC101`); 0.7 sorts stably by `time` so same-time controller sequences keep their list order ([sort keys](./semantics.md#sort-keys)). `controls.sort(key=lambda c: (c.time, c.number, c.value))` gives the old order. |
| **Silent trap** | Operations & CQS | `score.start()`<br>`score.end()` | `score.start()`<br>`score.end()` | A track without events no longer counts as time 0: in 0.6 it made `start()` return 0 for a score whose events all start later. `end()` of a `Quarter` or `Second` object whose events all end at or before 0 returned the smallest positive `float` in 0.6 and now returns the true latest end ([bounds and emptiness](./semantics.md#bounds-and-emptiness)). |
| **Silent trap** | Operations & CQS | `score.resample(tpq)`<br>`score.to(Tick)` | `score.resample(tpq)`<br>`score.to(Tick)` | A converted note's onset and end are rounded and its duration is their difference ([converting between units](./semantics.md#converting-between-units)). 0.6 rounded onset and duration separately for `Tick` and `Quarter` sources, so durations can differ by one tick, and notes that touched before conversion now still touch after it. `Second` sources already mapped both ends. |
| **Silent trap** | Operations & CQS | `x.adjust_time(original, target)` | `x.adjust_time(original, target)` | `Tick` results round half away from zero; 0.6 truncated toward zero, so warped times can differ by one tick. Anchors must be strictly increasing: repeated anchors such as `[0, 960, 960, 1920]`, accepted in 0.6, raise `ValueError`. The tempo, time signature and key signature in effect at `original[0]` are kept at `target[0]`; 0.6 dropped them when they lay before it ([warping time](./semantics.md#warping-time)). |
| **Silent trap** | Operations & CQS | `x.clip(start, end)` | `x.clip(start, end)` | The tempo and signatures kept by `clip` changed in three edge cases ([clip](./semantics.md#clip)). Among several at one time, 0.7 keeps the last in list order, the one in effect, where 0.6 kept the first. With `tail="keep"` (the default), tempo and signature events are kept up to `max(end, latest kept note end)` so overhanging note tails keep their tempo context. `clip(t, t)` returns no events, where 0.6 kept the tempo and signatures at `t`. |
| **Silent trap** | Constructors & I/O | `score.to_midi()`<br>`track.pianoroll()` with `Note(t, d, p, 0)` | `score.to_midi()`<br>`track.pianoroll()` | `to_midi()` skips all silent notes (`velocity == 0` or `duration == 0`, matching `render()`): 0.6 export wrote velocity-0 notes as two velocity-0 messages (two NoteOffs) and zero-duration notes as same-tick NoteOn/NoteOff pairs ([MIDI export](./semantics.md#midi-export)). `pianoroll()` skips velocity-0 notes (0.6 wrote them as 1 without `encode_velocity`, and as 0, erasing earlier notes, with it) while still marking `onset` and `offset` cells for zero-duration notes ([pianoroll](./semantics.md#pianoroll)). |
| **Silent trap** | Constructors & I/O | `score.to_midi()` | `score.to_midi()` | Melodic tracks take channels `0–8, 10–15` counting melodic tracks only. 0.6 counted every track, drums included, so a drum track shifted the channels of the tracks after it, and fifteen melodic tracks plus drums could put two melodic tracks on one channel. Files differ in channel numbers; reading them back gives the same tracks. |
| **Silent trap** | Constructors & I/O | `Score.from_file(path)` | `Score.from_file(path)` | A `(channel, program)` group that holds controls or pitch bends but no notes becomes a track; 0.6 dropped it with its events. `len(score.tracks)` can grow and positions of later tracks can shift. `score.tracks = score.tracks.filtered(lambda t: t.notes)` keeps only tracks with notes ([MIDI import](./semantics.md#midi-import)). |
| Breaking | Events & Pedals | `Note(True, 480, 60, 64)`<br>`Note(float("nan"), 1.0, 60, 64, ttype=Second)` | `Note(1, 480, 60, 64)` | A `Tick` time or duration takes integers only: 0.6 read `True` as 1, and 0.7 raises `TypeError`, as both already did for `1.0`. `Quarter` and `Second` values reject NaN and infinity with `ValueError` ([numeric input](./semantics.md#numeric-input)). |
| Breaking | Imports & Types | `class Tagged(NoteTick): ...` | `@dataclass class Tagged: note: Note; tag: str` | Public classes are final, so subclassing raises `TypeError`; 0.6 bound classes such as `core.NoteTick` could be subclassed. Wrap an object instead. Instances still have no `__dict__`; `Score` and `Track` now support weak references. |
